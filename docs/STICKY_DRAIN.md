# 会话保持（粘性）与平滑下线

在“注册 / 续约 / 健康探测 / 加权选路 / 熔断 / 重试”之上新增的一层能力：

- **会话保持**：同一会话在粘性有效期内稳定落到同一实例；
- **平滑下线**：实例宣告下线后不接新流量，等手上在途请求跑完、连接计数归零后才真正退出。

## 1. 会话粘性规则

### 1.1 会话标识

- 默认从请求头 **`x-session-id`** 读取（大小写不敏感）。
- 合法字符：字母、数字、`._:-@`；长度 1~128。
  例：`user-42`、`session.abc:1@tenant`。
- **缺失**或**明显不合法**（空串、含空格/控制字符/其他符号、超长）时：
  **不报错、不判无可用上游**，静默退化为普通加权选择，
  日志动作为 `NONE` 或 `INVALID_FALLBACK`。
- 粘性只在**同一服务（service）维度**内生效；不同服务的同名会话互不相干。

### 1.2 有效期语义（滑动 TTL）

- 绑定默认 TTL = **300 秒**（`SessionBinder(ttl_seconds=...)` 可调）。
- **滑动续期**：会话每次命中绑定（被使用）都会把到期时间刷新为 `now + TTL`。
  因此持续活跃的会话一直粘住；连续超过 TTL 没有请求才会失效。
- TTL 到期后该会话再来，动作记为 `EXPIRED_REBIND`，
  重新加权选择并绑定，`switch_reason=STICKY_TTL_EXPIRED`。
- 绑定只在请求**成功返回后**才对“新选/切换”生效；命中已有绑定时即滑动续期。
  失败实例不会成为会话的新宿主。

### 1.3 绑定实例不可用时的自动切换

绑定实例出现下列情况时，请求会**自动落到另一个可用实例**继续完成，
并在日志/决策里保留可解释的 `switch_reason`：

| 情况 | switch_reason | 是否清理绑定 |
| --- | --- | --- |
| 健康被摘除（DOWN） | `BOUND_INSTANCE_UNAVAILABLE` | 否（恢复后仍可粘回） |
| 熔断非 CLOSED | `BOUND_INSTANCE_UNAVAILABLE` | 否 |
| 本请求中该实例已失败、进入重试 | `BOUND_INSTANCE_FAILED` | 否（本次重试排除它） |
| 实例已注销 / 下线完成 / 租约过期，离开注册表 | `BOUND_INSTANCE_GONE` | 是（物理退出时清理） |
| 粘性 TTL 到期 | `STICKY_TTL_EXPIRED` | 覆盖为新绑定 |

- 只要服务里还有可服务实例，就不会因为“原来绑定的那个不在了”而整体失败。
- “**某个实例退出**”（切换到其他实例继续）与“**该服务已无可用实例**”
  是两种可区分的结论：后者才返回 `NO_AVAILABLE_UPSTREAM` / `ALL_UPSTREAMS_DOWN`。
- 重试时本请求已失败的实例会进入排除集合，**不会反复落在同一个失败实例上**。

### 1.4 状态查询

```
GET /admin/sessions/{service}/{session_id}
```

- 有效绑定：`{"bound": true, "binding": {instance, bound_at, expires_at, ttl_remaining}}`；
- 无有效绑定：`{"bound": false}`。

`GET /admin/status/{service}` 的 `sessions` 字段列出该服务当前全部有效绑定。

## 2. 平滑下线状态流转

```
SERVING ──begin_drain──▶ DRAINING ──在途归零──▶ DRAINED（已注销，墓碑）
   ▲                        │
   └── 同地址重新注册会复位墓碑
```

- **SERVING**：正常接新流量。
- **DRAINING**（下线中）：
  - 路由候选过滤立即剔除，**新请求不再选中它**；
  - 连接池门禁在计数提交前再复查一次，关闭“选路后才宣告下线”的并发窗口，
    竞争失败者收到 `INSTANCE_EXITING` 并自动改投其他实例（未真正调用上游，POST 等
    非幂等方法改投也安全，无重复副作用）；
  - **已经在处理的在途请求不受影响**，继续跑到正常返回；
  - 实例**豁免租约过期**（不会被过期摘除），且**续约被明确拒绝**
    （`INSTANCE_DRAINING`，HTTP 409）——杜绝“已宣布下线却被心跳复活”；
  - 每有一个连接租约释放就复查在途计数，**归零的那一刻**执行最终注销。
- **DRAINED**：已从注册表真正注销，连接计数 / 健康 / 熔断状态 / 指向它的会话绑定
  全部联动清理；保留一块短期墓碑，让“对已退出实例下线/续约”给出确定结论。
  同地址实例重新注册时墓碑自动复位。

### 2.1 受理结果（对调用方可区分）

`POST /admin/instances/{service}/{host}/{port}/drain`：

| 场景 | HTTP | code / status |
| --- | --- | --- |
| 正常受理（开始下线） | 200 | `status=DRAINING_STARTED`，含 `in_flight`、`deregistered` |
| 已在 DRAINING 中重复宣告 | 409 | `INSTANCE_ALREADY_DRAINING`（幂等，不扰动在途） |
| 实例不存在 / 已下线完成 / 已过期 | 404 | `INSTANCE_DRAIN_NOT_FOUND` |
| 下线过程中续约 | 409 | `INSTANCE_DRAINING` |
| 退出后续约 | 404 | `HEARTBEAT_UNKNOWN` |

- 受理时若无在途请求，`deregistered=true`，实例立即退出；
- 若有在途，`deregistered=false`，响应给出 `in_flight` 数量，
  实际退出发生在最后一个在途完成时（服务端日志可见
  “实例平滑退出完成 … 清理连接=x 清理会话绑定=y”）。

### 2.2 兼容范围

- 下线不改变请求/响应协议，仅改变选路与生命周期；不下线时行为与旧版完全一致。
- 会话保持可独立关闭：未注入 `SessionBinder` 时退化为纯加权选择。
- 主动注销（`DELETE`）与租约过期摘除也会走统一的退出清理
  （连接计数、健康/熔断、会话绑定），保证无残留。

## 3. 并发自洽保证

- 选路读取注册表快照；下线标记集合由独立锁保护，连接池在**同一把池锁**内
  “检查门禁 + 提交计数”，因此宣告下线与新请求获连无论怎样交织，
  新计数都不会记到退出实例上。
- 连接租约 `release()` 幂等；下线、切换、重试的所有路径都在 `finally` 精确释放一次，
  最终注销时对该实例计数做清退校验——不会泄漏、重复扣减或出现负数。
- 实例物理退出时按实例 id 清理指向它的会话绑定，不留下会错误命中的陈旧记录；
  健康 DOWN / 熔断 OPEN 属于“可恢复不可用”，保留绑定以便恢复后继续粘住。
